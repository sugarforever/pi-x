# Extension release automation

Goal: SemVer releases driven by Conventional Commits, with Release Please proposing version/changelog PRs and GitHub Actions publishing a checked extension ZIP.

- Add a shared version validator for package, lockfile, manifest and release metadata; tags must equal the packaged version and obey Chrome numeric-version constraints.
- Add an allowlisted, deterministic release packager with installation instructions and SHA-256 checksum. Test mismatched versions, archive contents, and accidental development artifact exclusion.
- Add reusable CI (unit checks, format, real packaged Chromium fixture) and a Release Please workflow that runs CI before release creation and packages/uploads within the same workflow to avoid GITHUB_TOKEN event suppression. Support manual artifact repair using an existing release tag.
- Document commit conventions, initial release version, setup permissions, release approval, artifact installation, manual updates, and recovery.
- Verify locally with complete tests, production build/archive inspection, browser checks, workflow validation and independent review. Workflows can execute remotely after these local changes are pushed to GitHub.
