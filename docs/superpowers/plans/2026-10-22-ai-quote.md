# AI Quote Implementation Plan

**Goal:** Build a local-first Chrome MV3 extension that drafts quotes in X's native composer using named prompts and Pi Durable tools.

**Architecture:** A content script binds the repost menu to its source post and inserts a composer toolbar. The service worker owns credentials, network access, and one IndexedDB-backed Pi Durable session per draft. Options manages provider settings, named prompts, writing examples, and optional research access. No automatic posting.

**Tech Stack:** TypeScript, esbuild, Pi Durable 1.4, Pi AI 1.4, IndexedDB, Vitest, Playwright.

## Global Constraints
- AI Quote runs the default prompt; regeneration uses the selected prompt.
- Selected-post text is untrusted content, never an instruction source.
- Tools are explicitly enabled per prompt: article reading, conversation context, writing samples, and Brave web search.
- Credentials remain in trusted extension contexts and local storage, never in page messages or durable transcripts.
- Preserve user edits; cancel on dialog close; never inject a late draft into a different composer.
- Research requires optional host permission; API origins are granted during settings save.
- Recovery restores job progress, not DOM write authority: only a matching live composer may accept its draft.

## Review Focus
- Recycled X menus must retain the right source post; quoted cards must not be mistaken for the source.
- A completed job must not overwrite typing or a regenerated draft.
- Cancellation/restart must not revive a cancelled job.
- Untrusted tool URLs cannot access local/private addresses or send provider credentials.
- Unsupported APIs, missing permissions, expired tabs, and tool limits must produce actionable errors.

## Tasks
- [x] Settings and protocol (`src/shared/*`, `tests/settings.test.ts`): test validation, prompt defaults, credential-free public settings and URL restrictions; implement settings/schema helpers.
- [x] Agent (`src/agent/*`, `tests/agent.test.ts`, `tests/tools.test.ts`): test actual Pi harness with a controlled OpenAI endpoint, tool invocation, cancellation and IndexedDB reopen; implement model provider, tools and bounded runs.
- [x] Background (`src/background/*`): implement trusted message routing, job ownership, persistence/recovery, permission checks, context tabs, connection test and cancellation; test ownership and job transitions.
- [x] X integration (`src/content/*`, `tests/content.test.ts`): test source extraction, menu injection, native Quote click, composer insertion and edit protection using DOM fixtures; implement toolbar, polling and cancellation.
- [x] Options and packaging (`src/options/*`, `scripts/build.mjs`, `manifest.json`, `README.md`): implement accessible settings, prompt/sample editing, permission requests, playground and data deletion; verify built extension and options in Chromium.
- [x] Run `npm run check`, browser integration tests, and independent code review; fix actionable findings. Document live-X and provider verification limits.

Execution is authorized by the user's “Go ahead”; implement in this workspace without a separate approval gate.

## Verification

Implemented with test-first coverage for settings, URL policy, Pi tool rounds, bounded runs, IndexedDB recovery, source extraction, edit protection, cancellation races, and composer reconnection. Packaged Chromium tests exercise all four tools against controlled network fixtures. Independent review findings were fixed and re-reviewed. Live X and a user-configured provider require an account-specific smoke test.
